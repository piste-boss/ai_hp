04 / 要点

7か条（優先順）

番号は取り組む順番です。上ほど効果が大きく、下は上ができてから効きます。

1

まず「見つかる」状態を切らさない

インデックスされていないページは、どんなに良い文章でも引用されません。AirOps の調査でも引用の55.8%は Google 上位20位以内のページでした。新しい記事ほど見えていなかったのが、これまでの最大の損失です。

  • 新規記事は公開時に canonical・OGP・Article スキーマ・サイトマップ・feed を必ず付ける（公開ルールどおり）
  • 15分Bing Webmaster Tools に登録し、Search Console からインポートしてサイトマップを提出する
  • 済FAQPage は151記事に設置済み（seo_build.py が3形式の FAQ を読めるよう拡張）。残り4記事は FAQ 節を書けば自動生成される
  • 済GA4 二重発火と canonical の不整合は 9/10 夕方の再デプロイで解消（3章）。以後は必ず release/public からデプロイする
2

冒頭3行で答えを言い切る

AIは記事を最後まで読んで要約するのではなく、質問に直接答えている段落を抜きます。AirOps によれば引用はページ冒頭30%に偏ります。前置きが長い記事は、本文がよくても抜く場所がありません。

  • H1 の直下に「誰向けか」「何ができるようになるか」「必要なもの」を3行で書く
  • 1段落に1つの主張。「〜できます」「〜が必要です」と言い切る。「〜かもしれません」は根拠がある箇所だけ
  • 「連携」「自動化」が具体的に何を指すかを冒頭で定義する
BEFORE

近年、Instagram を活用したマーケティングは中小企業にとって欠かせないものとなっています。しかし、投稿の作成や分析には多くの時間がかかり……

AFTER

Claude Code に Instagram の投稿データ（CSV）を渡すと、反応の良い投稿の傾向を表にまとめ、次週の投稿案を下書きできます。対象は投稿を週3回以上している事業者。必要なのは Claude Code と、インサイトの CSV エクスポートです。

3

質問と答えの形にする

AIへの入力は「質問文」です。見出しが質問そのもので、直下に答えがある記事は、質問と一致しやすく抜かれやすくなります。見出しの一致は AirOps が測った中で最も強いページ内要因でした。

  • H2 を読者の質問文にする（例：「Claude Code は Instagram に直接投稿できますか？」）
  • 記事末尾の FAQ は本文と重複してよい。むしろ同じ答えを短く言い直す場所
  • 比較・条件は表にする。「CSV を渡して分析する」「API で直接取得する」「人が画面から公開する」の3つは表で分けると誤解が消える
  • 1記事は500〜2,000語（日本語なら1,500〜5,000字）で1つの質問に絞る。長くなるなら分割して相互リンクする
4

一次情報を入れる

一般論はどのサイトにもあり、AIは選ぶ理由を持ちません。「この会社で実際にやった結果」だけが、他サイトではなくここを引用する理由になります。統計・数値データは HubSpot × Wix の調査で全エンジン共通の相関要素でした。

  • 実施前後の作業時間、対象件数、検証日、使ったツールのバージョンや条件を書く
  • 数字を作らない。測っていないなら「未計測」と書くか、書かない
  • 今月条件・手順・結果・制約・根拠のそろった独自事例を3本つくる（Instagram 分析、会計連携、現場記録のいずれか）
5

数字と表記をサイト全体でそろえる

AIは複数ページを横断して読みます。ページごとに実績や料金が違うと「どれが正しいか分からない情報源」と判定され、引用を避けられます。

  • 支援実績は「社数」「件数」「集計時点」を1つに決め、古い紹介文を書き換える
  • 料金はトップの「導入サポート 1時間 1万円（税込）」に合わせ、「3,000円〜」の記述を整理する
  • CTA の文言と遷移先を一致させる。「ココナラで相談する」なら実際にココナラへ
  • 会社名・サービス名・代表名の表記ゆれをなくす（Piste / 株式会社Piste / Piste AI EVANGELISTS の使い分けを決める）
  • 2026-09-10 夕方に統一した「正」: 支援実績「400社以上」、導入サポート「1時間 ¥10,000（税込）」、電話番号「0566-48-6580」。以後この表記だけを使う
6

誰が、いつ書いたかを示す

AIは「経験・専門性・権威・信頼」を手がかりに出典を選びます。著者が誰か、情報がいつのものか分からないページは、同じ内容でも後回しになります。目に見える更新日は、公開日より強い予測因子でした。

  • 各記事に著者名・公開日・実質的な更新日を本文に表示する（構造化データだけでなく、見える形で）
  • 著者ページ about.html と Person スキーマ、Article の author の @id 参照は設置済み。次は Person の description にある「200社以上」を本文と一致させる（5章）
  • 公的な制度や公式機能に触れるときは、一次資料（厚労省、Anthropic 公式ドキュメントなど）へリンクする
  • 主力記事は公開後3か月をめどに内容を見直し、変えたときだけ dateModified を更新する
7

引用されたかを毎月確認する

対策の効果は検索順位のようには見えません。引用されるページの約半分は毎月入れ替わる（AirOps）ので、見る場所を決めておかないと、やりっぱなしになります。

  • Search Console → 検索パフォーマンス → 「生成AI機能」フィルタで、表示回数と表示されたページを月1回記録する
  • GA4 の参照元で chatgpt.com perplexity.ai copilot.microsoft.com gemini.google.com を探索レポートに登録する
  • 月1回、ChatGPT・Perplexity・Google AIモードで実際に「碧南 AI導入 支援」「Claude Code 導入 サポート 愛知」などと聞き、出典に出るかを記録する
  • タグ設置範囲を広げた日（2026-09-10）を記録し、その前後の数字をそのまま伸び率として扱わない
05 / 構造化データ

構造化データの作り方

構造化データ（JSON-LD）は、ページに書いてある事実を「会社名はこれ、著者はこの人、料金はこれ」と機械に読める形で添える仕組みです。まず期待値を正しく置きます。

効くこと

会社名・住所・代表・料金・公開日といった事実をAIに誤読させない。複数ページで同じ組織・同じ人物だと機械的に確定できる。

Google のリッチリザルト（パンくず・記事の日付など）と Bing / Copilot の理解を助ける。

効かないこと

それ自体で引用を増やす力はほぼない。Ahrefs が2026年5月に1,885ページで検証し、追加後30日の引用変化は誤差の範囲だった。

本文に書いていない情報を構造化データにだけ入れても無視され、不一致はむしろ信頼を下げる。

原則4つ

  • 本文に見える事実だけを入れる。本文に無い料金・実績・住所を構造化データにだけ書かない。
  • JSON-LD を <head> に1種類1回。同じ型を二重に入れない。
  • @id でつなぐ。Organization と Person に固定の @id を持たせ、全記事の Article からそこを参照する。AIが「著者＝この人＝この会社の代表」を横断して確定できる。
  • 公開前に検証する。Google の「リッチリザルト テスト」と schema.org の「Schema Markup Validator」でエラーゼロにしてからデプロイ。

06 / 誤解

やらなくていいこと

×

llms.txt を置けば載る。Google は必須ではないと明言しています。設置済みなので、これ以上手をかけるより記事の冒頭を直すほうが効きます。

×

構造化データを増やせば引用が増える。Ahrefs の追跡調査では増えていません。5章の6種類を正確に作ったら、それ以上の型を追加するより本文を直します。

×

AI向けの隠しテキストやキーワードの詰め込み。通常のスパム判定と同じ扱いで、逆効果です。

×

投稿頻度を上げれば引用される。頻度は評価要因ではありません。公開後30日未満の記事はむしろ引用されにくい（AirOps）。当面は新記事より、すでに表示のある Instagram・スマレジ・PayPay 記事の改善を優先します。

×

1本に全部詰め込んだ長大な完全ガイド。5,000語を超えると500語未満より引用されません。分けて相互リンクします。

09 / 提案

ホットペッパービューティーの店舗情報を、ChatGPT・Gemini・Claude に優先的に引用させる施策

顧客サロン（ネイル・美容室など）への提案用です。ホットペッパー内の順位を上げる話ではなく、「碧南 ネイルサロン おすすめ」と AI に聞かれたときに、ホットペッパーに載せた店舗情報が出典として選ばれるための施策です。

前提：3つの AI は、それぞれ別の索引を見ている

AI店舗情報の入手元効く対策
ChatGPTBing の索引。米国では Yelp の口コミ・Foursquare のデータを提携で取り込んでいるが、日本ではその代わりがなく、Bing に索引されたホットペッパー・自社サイト・まとめ記事が主な情報源。Whitespark の2025年9月の調査では、地域推薦の根拠は Bing Places と口コミサイトで、Google の口コミは目立たなかったBing Places 登録、自社サイトの Bing 登録、ホットペッパー掲載ページが Bing に索引されているか確認
Gemini / Google AIモードGoogle 検索と Google ビジネスプロフィール（マップ）の情報、口コミ本文、写真、サービス一覧。2026年にビジネスプロフィールを Gemini に接続する機能が追加され、マップ内の「Ask Maps」も2026年8月に150か国超へ拡大ビジネスプロフィールの完成度と口コミ本文。サロンボードからの日次連携でホットペッパーの情報を Google に流す
ClaudeBrave Search の独自索引（Anthropic の再委託先一覧に記載。Google・Bing の結果は使わない）自社サイトとホットペッパー掲載ページが Brave に索引されているか site: 検索で確認。未索引なら Brave の URL 送信

共通するのは、どの AI も「ホットペッパーの中」を直接見るのではなく、索引に載ったページの本文と、口コミの文章を読んで店を選ぶことです。米国の SOCi の2026年調査では、ChatGPT が推薦した店舗は調査対象の1.2%（Google の地図上位3件は35.9%）で、推薦されること自体が希少です。逆に言えば、地域×業態で先に整えた店がほぼ独占します。

確認した事実：ホットペッパーは AI に読ませている

  • ホットペッパービューティーの robots.txt は、AI クローラー（GPTBot・ClaudeBot・PerplexityBot 等）を個別に禁止していない。User-agent: * で予約画面・フリーワード検索結果・条件検索ページだけを Disallow。サロン掲載ページは AI が読める。
  • ただし bingbot に Crawl-delay: 10 が設定されている。Bing の索引更新が遅いため、ChatGPT に情報が届くまで時間がかかる。ホットペッパー側の変更は「Bing には1〜2か月遅れる」前提で、自社サイトにも同じ情報を置く。
  • 掲載ページには JSON-LD がない。AI が読むのは「サロン紹介（150〜200字）」「こだわり（3項目×100〜150字）」「クーポン」「サロンデータ」「メニュー」「口コミ」のテキストそのもの。この文章が抜かれる。

施策（優先順）

1. 「抜かれる一文」をサロン紹介の冒頭にホットペッパー・ビジネスプロフィール・自社サイト共通

  • 地域・最寄駅・業態・強み・代表メニューの価格と所要時間・設備を1文で言い切る。例：「碧南市・碧南中央駅徒歩3分のネイルサロン。パラジェル専門、ワンカラー60分オフ込み5,500円、駐車場2台、日曜営業」
  • 「こだわり」3項目も同じ形。「〇〇が得意」ではなく「〇〇を△△の条件で提供」と条件つきで書く
  • AI が回答に使うのは100〜300トークンの自己完結した段落。詩的なキャッチコピーは抜かれないClaude Code で3媒体の文面を生成

2. 3媒体の表記を完全に一致させる店名・住所・電話・メニュー名・価格

  • ホットペッパー／Google ビジネスプロフィール／自社サイト／Instagram で、店名の表記（英字・カナ・記号）、住所、電話、メニュー名、価格を一字一句そろえる。AI は不一致があると「同じ店か確信できない」として引用を避ける
  • サロンボードから Google ビジネスプロフィールへの連携を申請すると、店名・写真・カテゴリ・住所・説明が日次で同期され、予約リンクにホットペッパーが設定される。ホットペッパーを「正」にして運用が楽になる
  • 自社サイトに NailSalon（または BeautySalon）スキーマを置き、sameAs にホットペッパー掲載ページ・Google マップ・Instagram の URL を入れる。3媒体が同一店舗だと機械的に確定するClaude Code で差分チェック

3. Gemini 対策 = Google ビジネスプロフィール日本で最も効く

  • カテゴリ（ネイルサロン）、サービス一覧と価格、属性（駐車場・子連れ可・予約必須）、営業時間を全部埋める。AI は「質問の条件」とプロフィールの項目を照合して店を選ぶ
  • 週3回の投稿（施術例・新メニュー・キャンペーン）、口コミ返信は48時間以内・返信率100%
  • 予約リンクにホットペッパーの掲載ページ。「Googleで予約」との直接連携はできないので、リンク方式にする

4. ChatGPT 対策 = Bing索引に載っていなければ存在しない

  • Bing Places for Business に登録（無料）。Google ビジネスプロフィールからのインポートが使える
  • 自社サイトを Bing Webmaster Tools に登録し、サイトマップを提出
  • Bing で site:beauty.hotpepper.jp 店名 を検索し、掲載ページが索引されているか確認。載っていなければ自社サイトからホットペッパーページへリンクして発見させる

5. 口コミを「引用できる文」にしてもらう件数より中身

  • Gemini は口コミの本文を読んで「この店は何が良いか」を判断する。「パラジェルで3週間持った」「駐車場があって子連れでも行けた」のように施術名・条件が入った口コミが引用される
  • 依頼時に「よければ受けた施術名を書いてください」と添えるのは可。内容の指定、来店実態のない依頼、自演は不可（ホットペッパー・Google とも掲載停止の対象）
  • 返信にも施術名と条件を含める。返信文も AI に読まれるClaude Code で返信下書き

6. 第三者のまとめ記事に載るAI はリスト記事を好む

  • HubSpot × Wix の調査で、リスト記事・比較記事は最も引用される形式。「碧南 ネイルサロン おすすめ」系の地域メディア・まとめ記事に掲載を依頼する
  • 自社ブログで自店を含む比較記事を書くのは自作自演になりやすく、AI が信頼しにくい。第三者媒体を優先する

7. 自社サイトの FAQAI の質問形に合わせる

  • 「料金はいくら？」「所要時間は？」「駐車場は？」「子連れで行ける？」「予約方法は？」の5問を本文と FAQPage スキーマの両方に置く。AI に来る質問は、ほぼこの5つ

質問ChatGPTGeminiClaude記録すること
