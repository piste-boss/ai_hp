「毎朝メール仕分けに30分」「営業フォローのメール文面を考える時間がない」「重要な問い合わせを見落として失注した」——中小企業の経営者・担当者にとって、Gmailを起点としたメール業務は時間と神経をすり減らす最大のボトルネックです。

そこで活用したいのが、AnthropicのAIコーディングツール Claude Code と Gmail の連携です。MCP（Model Context Protocol）経由でGmailをClaude Codeから直接操作することで、受信メールの自動仕分け・AIによる返信ドラフト生成・営業フォローの自動メール送信といった業務を 非エンジニアでも対話形式の指示だけで構築 できる時代になりました。

本記事では、Claude Code × Gmail連携で中小企業のメール業務を丸ごと自動化する実践パターンと、すぐに導入できる活用例を解説します。

1. なぜ今Claude Code × Gmail連携なのか

中小企業のメール業務には、以下のような共通の課題があります。

  • 問い合わせの見落とし：1日100通超の受信から重要案件を見つけ出す負担が大きい
  • 返信の質バラツキ：担当者が変わると返信トーン・内容が揺れる
  • 営業フォロー漏れ：商談後のフォローメールが続かず案件が冷める
  • メール作成の時間コスト：1通あたり10〜15分、1日5通で約1時間が消える

ここに Claude Code を組み合わせると、

  • 受信メールの内容をAIが読み取り、重要度・カテゴリで自動振り分け
  • 過去のやり取りを踏まえた返信ドラフトを自動生成
  • 商談後のフォローメールを段階的に自動送信
  • 社内連絡を要約してチームチャットに転送

といった業務が、月数千円〜の運用コストで実現できます。

2. Claude Code は Gmail のどんな作業を自動化できますか？

パターン1: 受信メールのAI仕分け＋通知

Gmail MCPサーバーをClaude Codeに接続することで（仕組みの全体像はMCP連携のガイドで解説しています）、受信メールの内容をAIに読ませて自動分類できます。

たとえば「物件問い合わせ」「クレーム対応」「請求書」「セミナー案内」といったラベルに自動振り分けし、緊急度の高いメールだけ即座にチャットツールへ通知。「朝の30分メール仕分けタイム」自体を消すことができます。

パターン2: AI返信ドラフト自動生成

「過去のメール履歴とよくあるFAQをふまえて、この問い合わせに対する返信ドラフトを書いて」とClaude Codeに依頼すると、状況に応じた返信文をドラフトとして下書きフォルダに保存。

担当者は内容を確認して微修正し、送信ボタンを押すだけ。返信1通あたりの作成時間が10分→2分に短縮できます。

パターン3: 営業フォロー＋社内連絡の自動化

商談記録（NotionやGoogle Sheets）から「3日経過したフォローが必要な案件」をClaude Codeが抽出し、過去のやり取りに合わせたフォローメールを自動下書き＆指定日時に送信予約。

社内連絡では、特定キーワード（決裁・承認・契約）を含むメールを要約し、Slack/Discordの該当チャンネルに転送する仕組みも構築できます。

Gmail の標準フィルタ・GAS・Claude Code の使い分け

「メールの自動化」は Claude Code でなくてもできる部分があります。道具ごとの得意分野を整理すると、Claude Code を使うべき場面がはっきりします。

やりたいことGmail 標準フィルタGoogle Apps Script（GAS）Claude Code
差出人・件名の固定条件でラベル付け◎ 設定画面だけで完結○△ 過剰
本文の意味を読んで分類（内見希望か価格相談か）× 単語一致のみ△ 自前で判定ロジックが必要◎ 文脈で判断できる
過去のやり取りをふまえた返信ドラフト×△ テンプレ差し込みまで◎
毎朝の定時実行× 受信時のみ◎ トリガーで安定○ PC 起動中に限る
スプレッドシートや Slack との連携×◎◎ MCP や API 経由
作った後の修正○△ コードを直す◎ 日本語で指示

結論として、固定条件の仕分けは Gmail のフィルタに任せ、「読んで判断する」「文面を書く」部分だけ Claude Code に担当させると、コストも失敗も最小になります。24時間止めずに動かしたい処理は、Claude Code に GAS のコードを書かせて GAS 側で定時実行させる組み合わせも有効です。

4. Claude Code と Gmail の連携はどう設定しますか？

Step 1: Gmail への接続方法を選ぶ（5分）

Claude Code から Gmail を扱う入口は2つあります。ほとんどの中小企業は A で十分です。

A. claude.ai の Gmail コネクタ（推奨）B. 自前の Gmail API ＋ MCP サーバー
準備時間5分1〜2時間
必要なものclaude.ai の有料プラン（Pro / Max / Team / Enterprise）でのログインGoogle Cloud のプロジェクトと OAuth 認証情報
権限の細かさGoogle の認証画面で許可した範囲スコープを自分で選べる（後述のポイント4）
向いている用途仕分け・返信ドラフト・要約など日常業務GAS や社内システムに組み込む本格運用

A は claude.ai のコネクタ設定で Gmail を接続し、Google の認証画面で許可するだけです。接続すると Claude Code 側に自動で表示され、/mcp を実行すると「claude.ai Gmail」が接続済みとして並びます。API キーでログインしている場合はコネクタが使えないので、claude.ai アカウントでログインし直してください（公式ドキュメント: MCP）。

Step 2: 自前で MCP サーバーを立てる場合の登録（B を選んだ人のみ・30分）

Google Cloud Console でプロジェクトを作成し、Gmail API を有効化して OAuth クライアントの認証情報を取得します。Anthropic 公式の Gmail 専用 MCP サーバーはないため、Gmail API を扱えるコミュニティ製の MCP サーバーを使うか、Claude Code に「Gmail API を呼ぶ MCP サーバーを書いて」と頼んで自作します。登録は次の1行です。

claude mcp add --transport stdio gmail -- npx -y <Gmail用MCPサーバーのパッケージ名>

--scope を省略すると今のプロジェクトだけで使える設定になります。全プロジェクトで使うなら --scope user、チームで設定ファイルを共有するなら --scope project（.mcp.json に保存）を付けます。認証情報のファイルは Git に入れない場所に置き、環境変数で渡してください。

Step 3: 自動化ロジックの作成（1〜2時間）

Claude Codeに「こういう条件のメールを、こう振り分けて、こんな返信ドラフトを作って」と日本語で依頼すれば、必要なスクリプトが数分で完成。具体例：

毎朝9時に未読メールを取得し、件名・本文をもとに「物件問い合わせ」「クレーム」「営業案件」「その他」に分類してラベルを付与。物件問い合わせは内見希望・価格相談・契約相談に細分類し、それぞれに合わせた返信ドラフトを下書きフォルダに保存して。

Step 4: 定期実行のセットアップ（30分）

定時実行には2つの公式機能があります。まず /loop で動かし、安定したら /schedule への移行を検討する順番が失敗しません。

  • /loop：今開いている Claude Code の中で「5分おき」「1時間おき」に同じ指示を繰り返す。最短1分間隔。セッションを閉じると止まるので、PC を起動している営業時間中の運用に向く。
  • /schedule（Routines）：クラウド側で毎朝9時などに自動実行する。PC の電源を切っていても動き、最短1時間間隔。「毎朝の仕分けと下書き作成」のような1日1回の処理はこちらが向く。

たとえば /loop 30m 未読メールを仕分けして、問い合わせには返信ドラフトを作って と打てば、30分ごとに仕分けと下書き作成が走ります。社内サーバーを別途用意する必要はありません。

Step 5: 運用しながらチューニング（継続）

「ラベル分類の精度を上げたい」「返信トーンをもっとフランクに」など、運用で気付いた点をClaude Codeに伝えれば即時修正。1週間の運用で自社業務に最適化されたメール自動化システムが完成します。

5. 導入時に押さえておきたい3つのポイント

ポイント1: 自動送信は段階的に解禁する

「受信仕分け→ドラフト作成→送信」のうち、まずは仕分けとドラフト作成までを自動化し、送信は人がチェックして行う運用から始めるのが安全です。AIの精度が確認できた段階で、定型的な返信のみ自動送信に切り替えると失敗が減ります。

ポイント2: 機密情報の扱いには細心の注意を

メール本文には個人情報・契約情報・財務情報が含まれます。Claude Codeはローカル環境で動作するため、データはAnthropicの学習に使用されないポリシーですが、送信先のWebhookやログ出力先のセキュリティ設定は必ず確認しましょう。

ポイント3: テンプレ集を整備して品質安定化

返信ドラフトのテンプレ集（FAQ・断り文句・営業フォロー文面）をClaude Codeに事前に渡しておくと、生成される文面の品質が安定します。社内のメール文化を踏まえたトーンマナーをテンプレとして資産化することで、属人化も解消できます。

ポイント4: 権限（スコープ）は「読み取り専用」から始める

Gmail API は、何を許可するかをスコープという単位で選べます。最初から全権限を渡さず、段階的に広げるのが安全です。

スコープできること使う段階
gmail.readonlyメールとラベルを読むだけ。書き込み不可1週目：仕分け精度の検証
gmail.labelsラベルの作成・変更のみ2週目：ラベル付けの自動化
gmail.compose下書きの作成・編集と送信返信ドラフトを下書きに保存する段階
gmail.modify完全削除以外の読み書きすべて既読・アーカイブまで任せる段階
https://mail.google.com/完全削除を含む全権限原則使わない

Google Workspace を使っている会社では、管理者が管理コンソールの「API の制御」で外部アプリのアクセスを制限していることがあります。設定前に管理者へ「この OAuth アプリに Gmail のスコープを許可してよいか」を確認しておくと、認証画面でエラーになって止まる時間を防げます。

ポイント5: フォローメールを自動送信するなら Google の送信者ガイドラインを守る

営業フォローを自動で送り始めると、送信数が一気に増えます。Google は メール送信者のガイドラインで、Gmail 宛てに送るすべての送信者に SPF または DKIM の設定、迷惑メール率 0.3% 未満などを求めており、1日 5,000 通以上送る場合は SPF・DKIM・DMARC の3つと、ワンクリックの配信停止が必須です。要件を満たさないと、自動化した途端に迷惑メール判定されてフォローが届かなくなります。

  • 自社ドメインに SPF・DKIM・DMARC が設定されているか、Google の 要件一覧と照らして確認する
  • Gmail の1日の送信上限（Google Workspace は 2,000 通、無料の Gmail は 500 通）を超えない設計にする
  • 案内メールには配信停止の方法を必ず書き、停止依頼は Claude Code で自動的に送信対象から外す
  • 送信ログをスプレッドシートに残し、誰に・いつ・どの文面を送ったかを後から追えるようにする

6. よくある質問

Q1. プログラミング知識がなくても本当に構築できますか

はい、Claude Codeは日本語の指示だけでスクリプトを生成・実行・修正してくれます。中小企業の経営者・現場担当者がご自身でセットアップする事例が増えています。最初の30分はやや戸惑うかもしれませんが、1度動かすと2回目以降は数分で構築できます。

Q2. Gmail以外のメールサービス、Outlookでも同じことができますか

可能です。Microsoft Graph API経由でOutlookとも連携できます。Claude Codeは複数のメール基盤に対応しており、Outlook・Gmail・iCloudメール・社内メールサーバーなど横断的に操作できます。

Q3. 既存のメールフィルターやラベルは活用できますか

はい。既存のラベル設計を維持したまま、AIによる分類ロジックを追加できます。手動運用していたラベル付けをAIに置き換えるだけでも、月10時間以上の時短になるケースが多いです。

Q4. 月額費用はどれくらいかかりますか

Gmail APIは基本無料（Google Workspaceの基本料金内）。Claude Codeの利用料は個人プランで月額数千円〜、業務用途でも月額1〜2万円台が一般的です。開発会社にメール自動化を依頼すると数十万円〜が相場ですが、月額1〜2万円で同等の仕組みが運用できる時代になりました。

Q5. AIの返信精度はどれくらい信頼できますか

定型的な問い合わせ返信であれば9割以上の精度で実用レベルに到達します。複雑な契約相談・クレーム対応など判断が分かれるケースは、ドラフト生成までで止めて人がチェックする運用が現実的です。社内のメール文化やFAQをClaude Codeに事前共有することで、精度はさらに向上します。

Q6. 誤送信を防ぐ仕組みは作れますか

作れます。もっとも確実なのは「Claude Code は下書きまで、送信ボタンは人が押す」運用です。自動送信に進む場合も、最初の2週間は送信先を自社ドメインのテスト用アドレスに固定し、宛先・件名・本文をスプレッドシートに記録してから送る手順を組み込みます。送信前に「宛先が顧客リストに存在するか」「同じ相手に24時間以内に送っていないか」をチェックさせるだけで、二重送信と宛先間違いの大半は防げます。

Q7. Google Workspace の管理者に事前に確認しておくことはありますか

3点あります。管理コンソールで外部の OAuth アプリに Gmail へのアクセスが許可されているか、社外への自動送信がコンプライアンス上問題ないか、1日の送信上限（2,000 通）に対して想定送信数が収まるか、です。個人の Gmail アカウントで試す場合は管理者確認は不要ですが、上限が 500 通と低い点と、業務メールを個人アカウントで扱う点に注意してください。
