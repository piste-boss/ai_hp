1. なぜ同じ作業で費用が10倍変わるのか

Claude Code の利用料は、扱った文章量に応じた従量制が基本です。読み込んだ資料の量と、生成した文章の量。この2つの合計に単価をかけたものが費用になります。

ここで効いてくるのがモデルごとの単価差です。Claude には、最も高性能な Opus、バランス型の Sonnet、軽量で高速な Haiku という系統があり、Opus と Haiku では同じ文章量あたりの単価が大きく開きます。つまり「日報の体裁を整えるだけ」の作業を最上位モデルにやらせると、必要のない性能に費用を払っていることになります。

逆に、複雑な業務フローの設計や、複数の資料を突き合わせて判断が必要な作業を軽量モデルにやらせると、やり直しが増えて結局は割高になります。安いモデルを使うことが節約ではなく、作業に見合ったモデルを選ぶことが節約だという点が出発点です。

2. Opus・Sonnet・Haiku はそれぞれ何が得意ですか？

系統性格向いている作業
Opus最も賢く、長い文脈を保ったまま複雑な判断ができる。単価は最も高い業務フロー全体の設計、複数資料を横断する分析、失敗が許されない重要作業
Sonnet実務の主力。多くの業務で十分な精度と、扱いやすい単価のバランス記事や提案書の作成、データ集計、日常的な自動処理の大半
Haiku軽量・高速・低単価。単純な判断や定型処理を大量にこなすのが得意分類・仕分け、定型文の生成、大量ファイルの一次処理

2026年に入ってからは、上位モデルにも長文をまとめて扱える大容量の枠が用意され、軽量モデル側も「補助役として大量に走らせる」用途を想定した構成が整ってきました。中小企業の実務では、Sonnet を基準にして、重い判断だけ Opus、単純作業は Haikuという三層構成が最も費用対効果が良くなります。

「一番賢いモデルを常用する」が損になる理由

最上位モデルは、答えを出すまでに考える量そのものが多くなります。単価が高いうえに扱う文章量も増えるため、費用は単純な単価差以上に開きます。毎日回す定型業務にこれを使い続けると、月額は想定の数倍になります。

3. 業務ごとにどのモデルを選べばよいですか？

業務推奨理由
自動化の仕組みを最初に設計するOpus設計を誤ると後の全作業に響く。ここだけは上位モデルで固める
ブログ記事・提案書の下書きSonnet文章品質と単価の釣り合いが最も良い領域
売上データの集計・グラフ化Sonnet計算と表現の両方が必要。軽量モデルだと取りこぼしが出やすい
受信した連絡の重要度仕分けHaiku判断基準が単純で件数が多い。速度と単価が効く
定型の返信文づくりHaiku型が決まっている作業。上位モデルの性能は不要
大量ファイルの名前付け・整理Haiku件数が多いほど単価差が効く典型例
契約書・見積の内容確認Opus見落としの損失が大きい。費用より精度を優先する場面
毎日の日報まとめSonnet または Haiku体裁を整えるだけなら軽量で十分。要約に含みを求めるなら中位へ

迷ったときの原則はシンプルです。間違えたときに取り返しがつかない作業ほど上位モデル、件数が多く型が決まっている作業ほど軽量モデル。この2軸で仕分ければ、ほとんどの業務は自然に割り振れます。

4. 費用が膨らむ典型パターン4つ

パターン1：会話を延々と続けてしまう

同じやり取りを続けると、それまでの会話全体を毎回読み直すことになり、後半になるほど1回あたりの費用が増えます。業務が一区切りついたら会話を切り、新しく始めるだけで費用は下がります。会話の切り方や読み込む範囲の絞り方は、コンテキスト管理の記事で詳しく扱っています。

パターン2：不要な資料まで読み込ませる

フォルダ全体を対象にすると、関係のないファイルまで読み込まれます。作業対象を必要な範囲に限定しておくことは、安全対策であると同時にコスト対策でもあります。

パターン3：定型作業に上位モデルを使い続ける

最初の設計時に上位モデルを使ったまま、日々の運用も同じ設定で回してしまうケースです。設計が終わったら運用用のモデルに切り替える、という手順を運用ルールに入れておきます。

パターン4：自動実行の頻度が過剰

「1時間ごとに確認」と設定したものの、実際は1日1回で十分だった、という例は珍しくありません。頻度は業務の実態に合わせて後から下げられます。まず粗く始めて、必要なら上げる順番が安全です。

5. 月額を予測可能にする5つの運用ルール

  1. 業務ごとに使うモデルを決めて書き出す：口頭で決めても運用では崩れます。「日報は軽量モデル、提案書は中位モデル」と一覧にしておきます。
  2. 作業対象のフォルダを限定する：読み込む範囲が決まっていれば、費用の上限も見えます。
  3. 1業務が終わったら会話を切る：長い会話を引きずらないだけで、月額は目に見えて変わります。
  4. 月初に前月の利用状況を確認する：どの業務にいくらかかったかを見る習慣をつけると、翌月の調整が具体的になります。
  5. 上限額を決めておく：想定を超えたら止まる仕組みを先に用意します。「気づいたら想定の3倍」を防ぐ最後の安全装置です。

6. 定額プランと従量課金、どちらを選ぶか

使い方向いている契約目安
毎日まとまった時間、対話しながら使う定額プラン1人が業務時間の多くを AI と進める場合
決まった処理を自動で回すだけ従量課金夜間に定型処理を走らせるだけ、といった用途
両方を並行して使う併用対話は定額、自動処理は従量で分けると読みやすい

少人数の会社では、まず従量課金で1か月試し、実際の金額を見てから定額プランを検討する順番が安全です。使っていない機能に先に払う必要はありません。

7. モデル選定を社内に定着させる4手順

決めたモデルの割り振りは、書いておかないと必ず崩れます。Claude Code には、業務ごとの決めごとをあらかじめ登録しておく仕組みがあるため、そこに組み込んでしまうのが確実です。

  1. 業務名とモデルの対応表をつくる：「日報の整形は軽量モデル」「提案書の下書きは中位モデル」というように一覧の形にします。3行から始めて構いません。
  2. その対応表を作業ルールとして登録する：Claude Code には、繰り返し使う指示や社内ルールを記憶させておく仕組み（CLAUDE.md）があります。ここに対応表を入れておけば、毎回モデルを指定し直す必要がなくなり、担当者が変わっても同じ運用が続きます。
  3. 定型業務は呼び出し1行にまとめる：よく使う業務は、手順とモデル指定をまとめて1つの呼び出しにできます。「日報まとめ」と打つだけで決めたモデルで決めた手順が走る状態にしておけば、選び間違いそのものが起きません。
  4. 月に一度だけ見直す：やり直しが多い業務は一段上のモデルへ、余裕がありすぎる業務は一段下へ。毎日調整しようとすると続きません。

この4手順まで済ませて、はじめて「決めたつもり」が「決まっている」状態になります。

よくある質問

モデルの切り替えは難しい操作が必要ですか。

設定で切り替えるだけで、専門知識は必要ありません。業務ごとにあらかじめ決めておけば、日々の運用で迷うこともなくなります。

軽量モデルだと品質が落ちませんか。

型の決まった作業であれば、体感できる差はほとんど出ません。差が出るのは、含みを読んだり複数の情報を突き合わせたりする作業です。そこだけ上位モデルに任せれば品質は保てます。

小規模でも導入する価値はありますか。

一人社長や数名の会社ほど、1人が抱える業務の幅が広く、自動化の効果は大きく出ます。まず1業務から始めて、費用と効果を実測してから広げる進め方をおすすめします。

途中で費用が想定を超えたらどうすればよいですか。

上限額を設定しておけば、超えた時点で止まります。そのうえで、会話の長さ・読み込む範囲・実行頻度の3つを見直せば、たいていは想定内に戻せます。

まとめ

Claude Code の運用コストは、使い方ではなく選び方で決まります。最上位モデルで全部やらせれば費用は膨らみ、軽量モデルで全部やらせればやり直しが増えます。取り返しのつかない作業は上位モデル、件数の多い定型作業は軽量モデル。この仕分けができていれば、同じ成果を出しながら月額を大きく下げられます。

そして、費用を読めるようにするために必要なのは、難しい設定ではありません。業務ごとに使うモデルを書き出し、作業範囲を限定し、上限額を決める。この3つだけで、月額は十分に予測可能になります。
