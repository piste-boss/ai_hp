## 1. Claude Code × SmartHR連携で実現できること

Claude Codeはターミナル上で動くAIコーディングツールで、自然言語で業務指示を出すと、API呼び出しやファイル操作、書類生成までこなしてくれます。SmartHRの公式APIと組み合わせることで、次のような人事労務作業がほぼ全自動になります。

- 新入社員の情報を伝えるだけで、SmartHRへの従業員登録と必要書類の依頼を自動セットアップ
- 入退社時の社会保険・雇用保険の手続きに必要な情報を自動で整理
- 勤怠データを取得し、残業時間・有給消化状況を自動集計してレポート化
- 年末調整の進捗（誰が未提出か）を自動チェックし、リマインド文面を作成
- 労務関連の通知文・案内文を社内トーンに合わせて自動下書き

「まずは入退社手続きの抜け漏れをなくしたい」というニーズから「勤怠と給与計算の連携まで自動化したい」という高度な運用まで、同じ仕組みで段階的に拡張できます。

## 2. なぜ中小企業の人事労務に自動化が必要なのか

人事労務は「ミスが許されないのに、繁忙期に集中する」特殊な業務です。担当が一人だと、その人が不在になった瞬間に業務が止まるリスクもあります。

| 業務 | 手作業の場合 | 自動化後 |
|------|------------|----------|
| 入社手続き（1名） | 書類準備・登録で90〜120分 | 情報整理と登録依頼で15分 |
| 勤怠データ集計 | 毎月半日〜1日 | 自動集計レポートで数分 |
| 年末調整の進捗管理 | 未提出者の確認・督促で数日 | 自動チェックとリマインド文生成 |
| 労務書類の作成 | 1件あたり30〜60分 | テンプレ自動生成で5分 |

少人数の会社こそ、この時間圧縮と「属人化の解消」の効果が大きく、担当者が変わっても同じ品質で業務を回せるようになります。

## 3. 連携の全体像と必要な準備

連携には大きく3つの要素が必要です。

### 3-1. SmartHR側の準備

- SmartHRアカウント（プランに応じてAPIアクセスを有効化）
- APIアクセストークンの発行（管理者権限の設定画面から取得）
- 従業員データベース・カスタム項目の整備
- 権限設定（取得・更新できる範囲を必要最小限に限定）

### 3-2. Claude Code側の準備

- 公式CLIのインストール
- 作業ディレクトリに人事労務用のフォルダを作成
- 環境変数ファイルにアクセストークンを保存（ファイルアクセス権限は本人のみに制限）
- 自社の就業規則・手続きフロー・書類テンプレートをまとめたメモリファイルを作成

### 3-3. 役割分担

| 担当 | 内容 |
|------|------|
| 人間 | 方針決定、内容の最終確認、提出・申請の承認 |
| Claude Code | 情報整理、API操作、データ集計、書類・文面の下書き |
| SmartHR | 従業員データ管理、電子申請、書類の収集・保管 |

人間は「方針決め」と「最終承認」だけに集中できる体制が理想です。

## 4. 具体的な活用シーン7選

### シーン1：入社手続きのワンストップ準備

「来月1日付で1名入社、職種は営業」とClaude Codeに伝えると、SmartHRへの従業員登録、本人への入力依頼項目の整理、必要書類チェックリストの作成までを一気に準備します。担当者は内容を確認して送信するだけです。

### シーン2：退社手続きの抜け漏れ防止

退職予定者が出た際に、社会保険の資格喪失・備品返却・アカウント停止などのやるべきことを自動でリスト化します。手続き漏れによるトラブルを未然に防ぎます。

### シーン3：勤怠データの自動集計とアラート

SmartHRや連携している勤怠データを取得し、残業が一定時間を超えた従業員、有給消化が進んでいない従業員を自動で抽出します。労務リスクを早期に発見できます。

### シーン4：年末調整の進捗管理と督促文の作成

年末調整シーズンに「誰が未提出か」を自動チェックし、対象者への丁寧なリマインド文面を作成します。担当者は送信先を確認するだけで済みます。

### シーン5：労務通知・社内案内の自動下書き

就業規則の改定通知、健康診断の案内、各種手続きのお知らせなどを、自社のトーンに合わせて下書きします。毎回ゼロから書く手間がなくなります。

### シーン6：従業員データの定期レポート化

従業員数の推移、入退社の動向、部署別の人員構成などを月次レポートとして自動生成します。経営判断や採用計画の材料になります。

### シーン7：他システムとのデータ連携

会計ソフトや勤怠ツール、給与計算ソフトと組み合わせ、従業員情報を一元的に同期します。同じ情報を複数のシステムに二重入力する作業をなくせます。

## 5. 自動化フローのサンプル構成

実際にClaude Codeで組むフローの一例です。

```
1. 入社情報の受け取り
   ├ 氏名・入社日
   ├ 職種・雇用形態
   └ 配属部署

2. SmartHR連携
   ├ 従業員登録
   ├ 本人への入力依頼項目を整理
   └ 必要書類チェックリスト生成

3. 進捗管理
   ├ 提出状況を自動追跡
   ├ 未提出者を抽出
   └ リマインド文面を作成

4. 人間による内容確認

5. 本人への依頼送信（承認後）

6. 手続き完了の記録とレポート化
```

このフローを一つのスキルとして登録しておけば、「新入社員の手続き準備して」とClaude Codeに伝えるだけで、ステップ1〜3が自動進行します。

## 6. 導入時に押さえるべきポイント

### 6-1. 個人情報の取り扱い範囲を限定する

APIで取得する項目を必要最小限に絞り、権限設定を厳格にしましょう。人事データは特に慎重な取り扱いが求められます。

### 6-2. アクセストークンの安全な管理

アクセストークンはコード内に直接書かず、環境変数ファイルに保存します。ファイル権限を本人のみに制限し、バックアップ対象から除外する設定にすると安全です。

### 6-3. 申請・提出は承認制にする

完全自動ではなく、「準備・整理まで自動・申請は人が承認」という運用がおすすめです。ミスのリスクを抑えながら、業務時間は大幅に短縮できます。

### 6-4. 就業規則をメモリ化する

自社の就業規則や手続きルールをメモリファイルにまとめておくと、AIが毎回ぶれずに同じ基準で対応するようになります。

### 6-5. 専門的な判断は社労士に確認する

複雑な労務判断や法令解釈はAIに任せきりにせず、必ず社会保険労務士などの専門家に確認しましょう。AIはあくまで準備・整理を担う役割です。

## 7. よくある質問

**Q1. プログラミングが全くできなくても使えますか？**
はい。Claude Codeは自然言語で指示するため、コードを書く必要はありません。最初の設定だけサポートを受ければ、その後は普通の会話で運用できます。

**Q2. SmartHR以外の労務ソフトでも同じことができますか？**
APIが公開されている労務・勤怠・給与計算ツールであれば、同様の連携が可能です。ツール選定からご相談いただけます。

**Q3. 個人情報の取り扱いは大丈夫ですか？**
従業員データはSmartHR側で管理され、Claude Codeには業務に必要な範囲のみが渡される設計にできます。アクセス権限・ログ管理も標準でサポートされています。

**Q4. 年末調整のような繁忙期だけ使うこともできますか？**
はい。年末調整や入社が集中する時期だけ重点的に活用し、閑散期は最低限の運用にするといった柔軟な使い方ができます。

**Q5. 既存のSmartHR運用にいきなり組み込めますか？**
既存の従業員データ・運用フローを活かしたまま連携可能です。現状の手続きフローを読み込み、AIが自社のやり方を学習します。

**Q6. 手続きにミスがあった場合のリカバリーは？**
Claude Codeは実行前に必ず「何を、誰に対して、いつ行うか」を提示するため、ミスを事前に発見しやすい設計です。万が一誤りが見つかった場合、訂正の案内文作成までAIに依頼できます。

**Q7. 月にどれくらいの工数削減になりますか？**
従業員規模にもよりますが、入退社・勤怠集計・各種通知を合わせて月10時間前後の削減が見込めるケースが多いです。年末調整シーズンはさらに効果が大きくなります。
